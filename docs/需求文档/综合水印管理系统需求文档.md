# 综合水印管理系统需求文档

## 1. 项目概述

### 1.1 项目名称
**水印管家** - 物业服务综合水印管理系统

### 1.2 项目背景
基于现有的微信小程序水印相机功能，扩展为一个综合性的水印管理系统，专门服务于物业管理行业。系统将支持用户管理、图片分组、对比分析、报告生成等功能，实现物业服务流程的数字化和可追溯性。

### 1.3 核心价值
- **提升物业服务质量**：通过前后对比，直观展示服务成果
- **加强过程管理**：完整的水印信息确保工作真实可靠
- **数据驱动决策**：基于历史数据的统计分析支持管理决策
- **提高工作效率**：自动化报告生成减少人工整理工作

### 1.4 目标用户
- 物业公司管理人员
- 一线维修/清洁/安保人员
- 业主委员会成员
- 第三方审计人员

### 2.2 用户管理系统

#### 2.2.1 用户角色定义
| 角色 | 权限范围 | 使用场景 |
|------|----------|----------|
| **超级管理员** | 系统全部功能，包括用户管理、数据管理、系统配置 | 物业公司管理者 |
| **区域管理员** | 管理特定区域的用户和数据 | 片区负责人 |
| **审核员** | 审核图片和报告，查看统计数据 | 质量管理人员 |
| **普通用户** | 拍照、上传、查看个人数据 | 一线工作人员 |
| **访客** | 只读权限，查看公开数据 | 业主委员会成员 |

#### 2.2.2 用户分组管理
**功能描述**：支持创建、编辑、删除用户分组，分组可按区域、楼栋、工作类型等维度划分。

**数据结构设计**：
```javascript
// 用户分组数据模型
const Group = {
  id: 'string',           // 分组唯一标识
  name: 'string',         // 分组名称（如：A区保洁组、B区维修组）
  type: 'enum',           // 分组类型：area/building/team/custom
  parentId: 'string',     // 父分组ID（支持层级结构）
  description: 'string',  // 分组描述
  members: [{
    userId: 'string',     // 用户ID
    role: 'enum',         // 分组内角色
    joinedAt: 'datetime'  // 加入时间
  }],
  createdAt: 'datetime',
  updatedAt: 'datetime',
  status: 'enum'          // active/disabled
}
```

**功能清单**：
- 创建分组：支持设置分组名称、类型、描述
- 编辑分组：修改分组信息、调整成员
- 删除分组：软删除，保留历史数据
- 分组树：支持多级分组层级展示
- 批量操作：批量添加/移除成员
- 分组统计：显示分组内成员数量、图片数量

#### 2.2.3 用户身份验证
**登录方式**：
- 微信小程序授权登录（主要方式）
- 手机号+验证码登录（备用方式）
- 管理员账号密码登录（后台管理）

**权限控制**：
- 基于RBAC（Role-Based Access Control）模型
- 支持细粒度权限配置
- 接口级别权限验证
- 数据级别权限隔离

### 4.3 数据库设计

#### 4.3.1 核心表结构

**用户表 (users)**
```sql
CREATE TABLE users (
  id VARCHAR(36) PRIMARY KEY,
  openid VARCHAR(64) UNIQUE NOT NULL,
  nickname VARCHAR(64),
  avatar_url VARCHAR(256),
  phone VARCHAR(20),
  role ENUM('super_admin', 'area_admin', 'reviewer', 'user', 'guest') DEFAULT 'user',
  status ENUM('active', 'disabled') DEFAULT 'active',
  last_login_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

**用户分组表 (groups)**
```sql
CREATE TABLE groups (
  id VARCHAR(36) PRIMARY KEY,
  name VARCHAR(128) NOT NULL,
  type ENUM('area', 'building', 'team', 'custom'),
  parent_id VARCHAR(36),
  description TEXT,
  status ENUM('active', 'disabled') DEFAULT 'active',
  created_by VARCHAR(36),
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  FOREIGN KEY (parent_id) REFERENCES groups(id),
  FOREIGN KEY (created_by) REFERENCES users(id)
);
```

**用户分组关联表 (user_groups)**
```sql
CREATE TABLE user_groups (
  id VARCHAR(36) PRIMARY KEY,
  user_id VARCHAR(36) NOT NULL,
  group_id VARCHAR(36) NOT NULL,
  role ENUM('admin', 'member', 'viewer') DEFAULT 'member',
  joined_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (group_id) REFERENCES groups(id),
  UNIQUE KEY uk_user_group (user_id, group_id)
);
```

**图片表 (images)**
```sql
CREATE TABLE images (
  id VARCHAR(36) PRIMARY KEY,
  url VARCHAR(512) NOT NULL,
  thumbnail_url VARCHAR(512),
  user_id VARCHAR(36) NOT NULL,
  group_id VARCHAR(36),
  template_type VARCHAR(32),
  watermark_hash VARCHAR(64),
  location_lat DECIMAL(10, 8),
  location_lng DECIMAL(11, 8),
  location_address VARCHAR(256),
  description TEXT,
  status ENUM('pending', 'approved', 'rejected') DEFAULT 'pending',
  captured_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  deleted_at DATETIME,
  FOREIGN KEY (user_id) REFERENCES users(id),
  FOREIGN KEY (group_id) REFERENCES groups(id),
  INDEX idx_user_id (user_id),
  INDEX idx_group_id (group_id),
  INDEX idx_captured_at (captured_at),
  INDEX idx_location (location_lat, location_lng)
);
```
